# Django ATS 要件定義書

**バージョン**: 1.0
**作成日**: 2025-12-27
**ステータス**: ドラフト

---

## 1. プロジェクト概要

### 1.1 ビジネスコンテキスト

| 項目 | 内容 |
|------|------|
| 提供者 | 採用コンサルティング会社 |
| 提供形態 | 顧客企業へのATS配布 |
| 顧客 | 採用活動を行う企業（コンサルティング顧客） |

### 1.2 システムの目的

1. **顧客企業の採用業務効率化**
   - 応募者・求職者の一元管理
   - 面接プロセスの標準化
   - ミスのない正確な管理

2. **データドリブンな採用支援**
   - 統一された評価基準
   - スコアリングによる客観的判断
   - 面接品質の向上

3. **採用コンサルタントとの連携**
   - 応募情報の一括登録
   - 複数チャネルからの応募統合

## 2. ユーザー種別と役割

### 2.1 ユーザー種別

| ユーザー種別 | 所属 | 説明 | 主な操作 |
|-------------|------|------|---------|
| **採用コンサルタント** | ATS提供側 | ATSを提供・運営。顧客企業の採用を支援 | 応募登録、全候補者閲覧、設定支援、レポート確認 |
| **人事担当者** | 顧客企業 | 顧客企業の採用担当。日常的にATSを操作 | 応募確認、選考管理、面接調整、内定処理 |
| **採用責任者** | 顧客企業 | 顧客企業の採用決定者 | 承認、レポート確認、最終判断 |
| **面接官** | 顧客企業 | 顧客企業の面接実施者 | 担当面接の実施、評価入力、フィードバック |
| **人材紹介会社** | 外部パートナー | 候補者を紹介する外部の紹介会社 | 自社紹介の候補者登録・閲覧・コメント |

### 2.2 アクセス権限マトリクス

| 応募登録 | ○ | ○ | × | × | ○ |

### 2.3 候補者データへのアクセス権限（詳細）

**セキュリティ上の重要事項**: 誰がどの候補者にアクセスできるかを厳密に制御

```
┌─────────────────────────────────────────────────────────────────────┐
│                    候補者データアクセス権限                          │
└─────────────────────────────────────────────────────────────────────┘

【フルアクセス（全候補者閲覧可能）】
┌─────────────────────────────────────────────────────────────────────┐
│ 採用コンサルタント ──▶ テナント内の全候補者                          │
│ 人事担当者 ──────────▶ テナント内の全候補者                          │
│ 採用責任者 ──────────▶ テナント内の全候補者                          │
└─────────────────────────────────────────────────────────────────────┘

【限定アクセス（条件付き閲覧）】
┌─────────────────────────────────────────────────────────────────────┐
│ 人材紹介会社A ──▶ 人材紹介会社Aが登録した候補者のみ                  │
│ 人材紹介会社B ──▶ 人材紹介会社Bが登録した候補者のみ                  │
│ （他社が紹介した候補者は一切見えない）                               │
│                                                                     │
│ 面接官 ──────────▶ 自分が担当する面接の候補者のみ                    │
│ （担当していない候補者は一切見えない）                               │
└─────────────────────────────────────────────────────────────────────┘
```

**アクセス権限の一覧表**:

| ユーザー種別 | 閲覧範囲 | 理由 |
|-------------|---------|------|
| 採用コンサルタント | **全候補者** | ATSを提供する側として全体把握が必要 |
| 人事担当者 | **全候補者** | 採用業務の主担当として全体管理が必要 |
| 採用責任者 | **全候補者** | 最終判断者として全体把握が必要 |
| 人材紹介会社 | **自社紹介のみ** | 競合他社の紹介情報を見せない（情報保護） |
| 面接官 | **担当面接のみ** | 必要最小限の情報アクセス（セキュリティ） |

**アクセス制御の実装ルール**:

| ルール | 説明 |
|--------|------|
| 登録者情報の記録 | 候補者登録時に「誰が登録したか」を必ず記録 |
| 紹介会社の識別 | 人材紹介会社ユーザーは所属会社IDを持つ |
| 面接担当の紐付け | 面接レコードに面接官IDを紐付け |
| 権限チェック | 候補者一覧・詳細アクセス時に権限を検証 |

**コメント閲覧権限**:

| ユーザー | コメント閲覧範囲 |
|---------|-----------------|
| 候補者にアクセス可能なユーザー | その候補者の全コメントを閲覧可能 |
| 候補者にアクセス不可のユーザー | コメントも見えない |

※ 候補者ページにアクセスできれば、その候補者に関する全コメントが見える仕様

## 3. 機能要件

### 3.1 応募入力機能（統合応募フォーム）

**目的**: 複数チャネルからの応募を一元化し、顧客の管理コストを大幅削減

#### 3.1.1 統合応募フォームのコンセプト

**現状の課題**:
```
採用コンサルタント ──── LINE ────┐
求人媒体 ──────────── メール ───┤
人材紹介会社A ─────── Slack ────┼──▶ 顧客が手動で転記 ──▶ 管理表
人材紹介会社B ─────── チャット ──┤        ↓
自社HP応募 ─────────── メール ───┘    ミス・漏れ・工数大
```

**ATSで実現する姿**:
```
採用コンサルタント ──┐
求人媒体 ──────────┤
人材紹介会社A ──────┼──▶ 統合応募フォーム ──▶ 自動でATS登録
人材紹介会社B ──────┤      （1つの入口）        ↓
自社HP/直接応募 ────┘                      転記不要・ミスなし
```

#### 3.1.2 アクセス・認証設計

| 項目 | 仕様 |
|------|------|
| フォームURL | テナント（顧客企業）ごとに専用URL発行 |
| アクセス方法 | ログイン必須（全ユーザー） |
| 権限制御 | ログイン後、ロールに応じてアクセス可能ページを制限 |
| 入力者記録 | ログインユーザーを自動で記録（誰が登録したか追跡可能） |

**フォームにアクセスできるユーザー**:

| ユーザー種別 | アクセス方法 | 用途 |
|-------------|-------------|------|
| 採用コンサルタント | ログイン後、フォームへ | 推薦候補者の登録 |
| 人材紹介会社担当者 | ログイン後、フォームへ | 紹介候補者の登録 |
| 顧客企業の人事担当 | ログイン後、フォームへ | 自社流入・直接応募の登録 |

#### 3.1.3 対応する応募チャネル

| チャネル | 入力者 | 登録方法 |
|---------|--------|---------|
| 採用コンサルタント推薦 | コンサルタント本人 | 手動入力 / CSVインポート |
| 求人媒体（Indeed, リクナビ等） | 人事担当者 | CSVインポート |
| 人材紹介会社 | 紹介会社担当者 | 手動入力 / CSVインポート |
| 自社HP応募 | 人事担当者 | 手動入力 |
| 直接応募（持ち込み） | 人事担当者 | 手動入力 |

#### 3.1.4 応募登録フォームの入力項目

**入力項目（全チャネル統一）**:

| カテゴリ | 項目 | 必須 | 備考 |
|---------|------|:----:|------|
| 基本情報 | 氏名 | ○ | |
| | ふりがな | | |
| | メールアドレス | ○ | 重複チェックに使用 |
| | 電話番号 | | |
| | 生年月日 | | |
| | 性別 | | |
| 応募情報 | 応募求人 | ○ | プルダウン選択 |
| | 応募チャネル | ○ | 選択式（統一） |
| | 紹介元（会社名・担当者名） | | チャネルに応じて表示 |
| 職歴 | 現職企業名 | | |
| | 現職役職 | | |
| | 経験年数 | | |
| 希望条件 | 希望年収 | | |
| | 現在の年収 | | |
| | 転職時期 | | |
| 添付書類 | 履歴書 | | PDF/Word/画像 |
| | 職務経歴書 | | PDF/Word/画像 |
| その他 | 備考・推薦コメント | | 自由記述 |
| システム自動 | 登録者 | 自動 | ログインユーザー |
| | 登録日時 | 自動 | システム日時 |

#### 3.1.5 通知機能

| イベント | 通知先 | 通知方法 |
|---------|-------|---------|
| 新規応募登録時 | 顧客企業の人事担当者 | メール / システム内通知 |
| 新規応募登録時 | 担当コンサルタント | メール / システム内通知 |

#### 3.1.6 一括登録機能（CSVインポート）

- CSVテンプレートのダウンロード
- CSVアップロードによる一括登録
- インポート結果のプレビュー・確認
- エラー行の特定と修正支援
- 重複候補者の検出と処理選択

### 3.2 候補者管理機能

**目的**: 求職者情報の一元管理とデータドリブンな評価

#### 3.2.1 候補者プロフィール

| カテゴリ | 項目 |
|---------|------|
| 基本情報 | 氏名、ふりがな、生年月日、性別、連絡先 |
| 職歴 | 現職/前職、在籍期間、役職、業務内容 |
| スキル | 資格、言語、技術スキル、経験年数 |
| 希望条件 | 希望年収、希望勤務地、転職時期、勤務形態 |
| 評価情報 | スコア、評価コメント、面接履歴 |

#### 3.2.2 候補者スコアリング

**自動スコアリング項目**:

| 評価軸 | 評価基準 | 配点 |
|-------|---------|------|
| 経験マッチ度 | 求人要件との職歴マッチ | 0-25点 |
| スキルマッチ度 | 必須スキル・歓迎スキルの合致 | 0-25点 |
| 年収マッチ度 | 希望年収と提示可能額の乖離 | 0-20点 |
| 転職意欲 | 転職時期、応募動機の明確さ | 0-15点 |
| カルチャーフィット | 価値観、志向性 | 0-15点 |

**スコアの活用**:
- 書類選考の優先順位付け
- 面接官への事前情報として表示
- 採用確率の予測（将来）

#### 3.2.3 候補者個別ページ

**表示内容**:
- プロフィール情報（編集可能）
- 応募履歴・選考状況
- 面接履歴・評価結果
- タイムライン（活動履歴）
- コメント・ディスカッション（チャット形式）
- 添付ファイル一覧

**操作機能**:
- ステータス変更
- 面接スケジュール登録
- 評価入力
- コメント投稿
- ファイルアップロード

### 3.4 選考管理機能

**目的**: 選考プロセスの可視化と進捗管理

#### 3.4.1 選考ステータス

```
新規応募 → 書類選考中 → 書類通過 → 一次面接 → 二次面接 → 最終面接 → 内定 → 内定承諾 → 入社
                ↓           ↓          ↓          ↓          ↓       ↓
              書類不合格    辞退        不合格      不合格      不合格   内定辞退
```

## 6. Google Sheets連携について

### 6.1 連携の目的

| 目的 | 説明 |
|------|------|
| 顧客への透明性 | 顧客がデータを直接確認できる |
| バックアップ | Spreadsheetを二次バックアップとして活用 |
| レポート共有 | 経営層へのレポート共有が容易 |
| 既存業務との統合 | Spreadsheet中心の業務からの移行を容易に |

### 6.2 連携パターン

**推奨: 案C「DB→Sheets同期（一方向）」**

```
┌─────────────┐        ┌─────────────┐
│  Django ATS  │ ────▶ │ Google Sheets│
│ (PostgreSQL) │  同期  │ （閲覧用）   │
└─────────────┘        └─────────────┘
     ↑ マスター              ↓ 読み取り専用
     │                       │
  全操作はATS経由         レポート確認
```

**理由**:
1. データ整合性を保証（DBがマスター）
2. 競合・上書きリスクなし
3. API制限の影響が少ない（書き込みのみ）
4. 顧客はSpreadsheetで確認可能

### 6.3 同期内容

| シート名 | 同期タイミング | 内容 |
|---------|--------------|------|
| 候補者一覧 | 日次 | 全候補者のサマリー |
| 応募状況 | リアルタイム | 新規応募時に追加 |
| 選考進捗 | ステータス変更時 | ステータス履歴 |
| 面接結果 | 評価入力時 | 面接評価サマリー |
| 月次レポート | 月次 | 採用KPI |
