# Google Sheets 連携ガイド

**バージョン**: 1.0
**作成日**: 2025-12-27

このドキュメントでは、Django ATSとGoogle Sheetsの連携について、技術的な詳細と推奨アーキテクチャを説明します。

---

## 1. Google Sheets連携とは？

### 1.1 概要

Google Sheets連携とは、Django ATS（Webアプリケーション）とGoogle Spreadsheet（Googleのオンライン表計算ソフト）をプログラムで接続し、データをやり取りすることです。

```
┌─────────────┐                    ┌─────────────────┐
│  Django ATS  │ ◀──── API ────▶ │ Google Sheets    │
│ (Webアプリ)  │                    │ (スプレッドシート) │
└─────────────┘                    └─────────────────┘
```

### 1.2 なぜGoogle Sheetsを使うのか？

| メリット | 説明 |
|---------|------|
| **顧客の馴染みやすさ** | ExcelやSpreadsheetは多くの人が使い慣れている |
| **データの可視性** | 顧客が自分でデータを確認できる |
| **バックアップ** | Googleがデータを自動保存 |
| **共有の容易さ** | リンク一つで社内共有可能 |
| **コスト** | Google Workspace利用者は追加コスト不要 |

### 1.3 デメリット・制限

| デメリット | 説明 |
|-----------|------|
| **パフォーマンス** | 5,000行を超えると遅くなる |
| **データ整合性** | トランザクション（一括処理の保証）がない |
| **API制限** | 1分間に300リクエストまで |
| **同時編集の競合** | 同時に編集すると上書きリスク |
| **検索の限界** | 複雑な検索はできない |

## 2. 連携パターンの比較

### 2.1 パターン一覧

| パターン | 概要 | データの流れ |
|---------|------|------------|
| **A: DB Only** | データベースのみ使用 | なし |
| **B: Sheets Only** | Sheetsのみ使用 | なし |
| **C: DB→Sheets（推奨）** | DBがマスター、Sheetsにエクスポート | 一方向 |
| **D: Sheets→DB** | Sheetsがマスター、DBにインポート | 一方向 |
| **E: 双方向同期** | 両方を同期 | 双方向 |

### 2.2 パターン詳細

#### パターンA: DB Only（現在の構成）

```
┌─────────────┐
│  Django ATS  │
│ (PostgreSQL) │ ← すべてのデータはここに保存
└─────────────┘
```

**メリット**: 高速、安全、スケーラブル
**デメリット**: 顧客がデータを直接見れない

---

#### パターンB: Sheets Only

```
┌─────────────┐              ┌─────────────────┐
│  Django ATS  │ ◀─── API ───▶│ Google Sheets    │
│ (DBなし)     │              │ (データ保存)      │
└─────────────┘              └─────────────────┘
```

**メリット**: 顧客がデータを直接編集可能
**デメリット**: パフォーマンス問題、整合性リスク

---

#### パターンC: DB→Sheets（推奨）🌟

```
┌─────────────┐              ┌─────────────────┐
│  Django ATS  │ ───同期───▶ │ Google Sheets    │
│ (PostgreSQL) │              │ （閲覧・レポート用）│
│   [マスター]   │              │                 │
└─────────────┘              └─────────────────┘
      ↑                              ↓
  すべての操作                   レポート確認
  はATS経由                      データ閲覧
```

**メリット**:
- DBの信頼性を維持
- 顧客はSpreadsheetでデータ確認可能
- 競合・上書きリスクなし

**デメリット**:
- 顧客はSpreadsheetを編集できない（閲覧のみ）

---

#### パターンD: Sheets→DB

```
┌─────────────────┐              ┌─────────────┐
│ Google Sheets    │ ───同期───▶ │  Django ATS  │
│ （データ入力）     │              │ (PostgreSQL) │
│    [マスター]      │              │              │
└─────────────────┘              └─────────────┘
      ↑                              ↓
  顧客がデータ入力                検索・分析
```

**メリット**:
- 顧客がSpreadsheetでデータ入力可能
- 既存のSpreadsheet運用を活かせる

**デメリット**:
- 同期の複雑さ
- 競合リスク

---

#### パターンE: 双方向同期

```
┌─────────────┐              ┌─────────────────┐
│  Django ATS  │ ◀───同期───▶ │ Google Sheets    │
│ (PostgreSQL) │              │                 │
└─────────────┘              └─────────────────┘
```

**メリット**: 完全な柔軟性
**デメリット**:
- 実装が非常に複雑
- 競合解決が困難
- 推奨しない

## 3. 推奨アーキテクチャ（パターンC）

### 3.1 なぜパターンCを推奨するか

1. **データ整合性の保証**: DBがマスターなので、データの矛盾が起きない
2. **パフォーマンス**: 日常操作はDB経由（高速）
3. **顧客満足**: Spreadsheetでデータ確認可能
4. **運用の簡潔さ**: 一方向同期なので複雑さが少ない

### 3.2 システム構成図

## 4. 技術的な仕組み

### 4.1 Google Sheets API

Google Sheets APIは、Googleが提供する公式のAPI（プログラムからの操作インターフェース）です。

**できること**:
- スプレッドシートの作成・削除
- シートの追加・削除
- セルの読み書き
- 書式設定
- 共有設定

### 4.2 認証方式（サービスアカウント）

```
┌─────────────┐         ┌─────────────────┐         ┌─────────────┐
│  Django ATS  │ ──────▶ │ Google Cloud    │ ──────▶ │ Sheets API  │
│             │  認証    │ (サービスアカウント)│  許可    │             │
└─────────────┘         └─────────────────┘         └─────────────┘
```

**サービスアカウントとは？**
- Googleが発行する「ロボット用のGoogleアカウント」
- 人間の代わりにプログラムがAPIを使うための仕組み
- JSON形式の認証ファイルで管理

### 4.3 使用ライブラリ

| ライブラリ | 役割 |
|-----------|------|
| `gspread` | Google Sheets APIのPythonラッパー |
| `google-auth` | Google認証ライブラリ |

### 4.4 コード例（読み書き）

```python
# スプレッドシートを開く
spreadsheet = client.open_by_key("スプレッドシートID")

# シートを取得
sheet = spreadsheet.worksheet("候補者一覧")

# データを読み取り
all_records = sheet.get_all_records()  # [{'氏名': '山田', 'メール': '...'}, ...]

# 行を追加
sheet.append_row(['田中花子', 'tanaka@example.com', '090-1234-5678'])

# 特定のセルを更新
sheet.update('A2', '更新された値')
```

## 5. API制限と対策

### 5.1 制限一覧

| 制限 | 値 | 対策 |
|------|-----|------|
| リクエスト数 | 300回/分/プロジェクト | バッチ処理で削減 |
| ユーザー別 | 60回/分/ユーザー | キューイングで分散 |
| セル数 | 1シート1000万セル | アーカイブで分割 |
| ファイルサイズ | 100MB | 添付は別管理 |

### 5.2 パフォーマンス対策

```python
# ❌ 悪い例: 1行ずつ追加（10回のAPIコール）
for row in rows:
    sheet.append_row(row)

# ✅ 良い例: まとめて追加（1回のAPIコール）
sheet.append_rows(rows)
```

## 7. 導入手順（GCP設定）

### 7.1 事前準備

1. **Googleアカウント**: Google Workspace推奨
2. **GCPアカウント**: Google Cloud Platform

### 7.2 設定手順

#### Step 1: GCPプロジェクト作成

1. [Google Cloud Console](https://console.cloud.google.com/) にアクセス
2. 新しいプロジェクトを作成（例: `django-ats`）
3. プロジェクトを選択

#### Step 2: Google Sheets API有効化

1. 左メニュー「APIとサービス」→「ライブラリ」
2. 「Google Sheets API」を検索
3. 「有効にする」をクリック
4. 同様に「Google Drive API」も有効化

#### Step 3: サービスアカウント作成

1. 左メニュー「IAMと管理」→「サービスアカウント」
2. 「サービスアカウントを作成」
3. 名前: `django-ats-sheets`
4. 「作成して続行」→ロールは不要→「完了」

#### Step 4: 認証キー発行

1. 作成したサービスアカウントをクリック
2. 「キー」タブ→「鍵を追加」→「新しい鍵を作成」
3. 「JSON」を選択→「作成」
4. JSONファイルがダウンロードされる（大切に保管！）

#### Step 5: Django設定

```python
# .env ファイル
GOOGLE_SHEETS_ENABLED=True
GOOGLE_CREDENTIALS_FILE=/path/to/credentials.json
GOOGLE_TEMPLATE_SPREADSHEET_ID=テンプレートのID
```

#### Step 6: スプレッドシート共有

1. テンプレートスプレッドシートを作成
2. サービスアカウントのメールアドレスを共有に追加
   - メールアドレス: `xxxxx@project-id.iam.gserviceaccount.com`
   - 権限: 編集者

## 9. よくある質問

### Q1: 顧客がSpreadsheetを編集したらどうなる？

**A**: パターンCでは、Spreadsheetは「読み取り専用」として運用します。共有設定で「閲覧者」権限のみを付与すれば、編集はできません。

### Q2: Googleの障害時はどうなる？

**A**: DBがマスターなので、ATSは正常に動作します。Spreadsheetへの同期は障害復旧後に再開されます。

### Q3: 大量データ（1万件以上）でも使える？

**A**: DBは問題ありません。Spreadsheet側は5,000件を超えると遅くなるため、古いデータをアーカイブするか、サマリーのみを同期する運用を推奨します。

### Q4: 既存のSpreadsheetをインポートできる？

**A**: はい。CSVエクスポート→ATSにインポートの流れで対応可能です。
